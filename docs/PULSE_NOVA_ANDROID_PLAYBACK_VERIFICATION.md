# PULSE-NOVA Android playback verification

## Verified automated coverage
`node tools/ai_pulse_local/test_offline_composer.cjs` checks RIFF chunk size, PCM format, 22,050 Hz, mono 16-bit payload length, deterministic seed, different seed, silence and all three styles. It **does not** execute Android Chrome/WebView or verify the loudspeaker.

## Manual phone test (requires actual Android device)
1. Save `tools/ai_pulse_local/pulse_nova_android_offline.html` to the phone and open in Chrome or another browser that permits local HTML. If local file navigation is blocked, use an Android app asset WebView instead.
2. Tap **Generate WAV** (108 BPM, 4 bars, seed 42). Confirm status reads WAV ready, no error and audio controls appear.
3. Tap **Play**. Verify audible music and pause/resume. Playback must start only after the user gesture.
4. Tap **Save WAV**. Verify a WAV file is saved. Reopen it using the phone's audio player and verify sound.
5. Turn on airplane mode, reload the saved HTML, repeat steps 2–4. No network should be required.
6. Repeat after rotating the screen, locking/unlocking it and using headphones/Bluetooth if available. Record any audio interruption or focus problem.
7. Try 2 and 16 bars, each style, and repeated generation. Watch for UI freezes, playback failures, and memory pressure.
8. Record Android version, browser/WebView version, device, pass/fail for playback and download, and observed errors. Do not mark device verification passed without these results.

## Android WebView integration guidance
- Bundle the HTML in `app/src/main/assets/` and load via `WebViewAssetLoader` where available; do not assume a raw `file://` page has the same permissions as HTTPS.
- Enable JavaScript only for the trusted bundled page. Do not expose a broad JavaScript bridge to untrusted websites.
- Keep `mediaPlaybackRequiresUserGesture = true`; the existing Play button provides the gesture.
- Respect Android lifecycle: pause playback when appropriate, and test audio focus alongside the app's native player.
- Android `DownloadManager` cannot directly download a `blob:` URL. WebView hosts must implement a trusted export bridge or decode and save generated bytes through the Storage Access Framework. Avoid enabling universal file access.
- Native WebView `Blob` URL playback and downloads are distinct tests. A successful `<audio>` playback does not prove export works.
- A successful Gradle build or Node VM test is not evidence of WebView behavior.
